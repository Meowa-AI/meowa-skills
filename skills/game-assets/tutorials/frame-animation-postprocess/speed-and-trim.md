# 加速与裁帧：让动作适合游戏节奏

生成的动作通常偏慢：起手蓄力长、收招还原慢，两三秒的动作在游戏里显得拖沓。游戏版可以在**不破坏动作本身**的前提下压缩节奏。原则见[后处理总览](README.md)。

## 1. 先按阶段看动作

把每段动作分成**起手、发力、收招**三个阶段，再决定每段怎么处理：

- **发力段**（拳头打出、砸下、跳起）是动作的核心，尽量保留原帧；
- **起手段**（抬手、下蹲蓄力）和**收招段**（还原到站姿）是主要的压缩对象。

找到命中或发力的那一帧，作为后续游戏判定的依据，同时记录在元数据里。

## 2. 常用处理方式

| 问题 | 处理方式 |
|---|---|
| 跳跃前蓄力太久 | 蓄力段隔帧抽取，或只保留下蹲的关键几帧 |
| 连击衔接不上，每一招都完整抬手、完整还原 | 裁掉每招前的抬手和每招后的还原，只保留进入发力的几帧和收势后的准备姿势，让下一招能直接接上 |
| 动作首尾有完全静止的帧 | 裁掉首尾的静止帧，保留首帧和末帧本身 |
| 整体偏慢 | 在游戏里整体提高播放速度；各动作可以设置不同倍率 |
| 收招拖得太长 | 收招段隔帧抽取，保留回到站姿的最后一帧，避免切回待机时跳位 |

连击这类单次动作，生成时使用 `--animation-mode non_loop`，避免模型为回到首帧补出冗余的还原帧，后处理也更省事。

抽帧时保持所选帧的原始像素、画布与锚点，不插帧、不缩放。抽帧后按游戏实际速度回放，确认发力仍然清楚、没有突然加速或卡顿。

## 3. 倒放与拆段复用

同一段动画可以复用出新的动作，节省生成：

- 消失动画倒放成"出现"，例如传送的消失与出现；
- 躲进护罩的动画倒放成"出来"；
- 倒地动画拆出前半段作"被击倒"，倒放作"起身"。

倒放后检查运动是否合理：头发、尾巴、衣摆的摆动方向，以及脚步是否显得像在倒着走。不合理时只截取能倒放的部分。

## 4. 剔除问题帧

生成结果里常有少数问题帧，只要不承担关键动作，就可以在后处理中去掉：

- **大面积特效帧：** 冲击线、星芒、落地尘环等只出现在少数帧时，跳过这些帧。
- **背景漂移：** 表情夸张的动作（嘲讽、鬼脸）可能在后段背景变色或出现放射线。前段动作完整时，截取到漂移之前，再倒放回首帧，形成一个往返动作。

剔除后重新回放，检查节奏和衔接。问题出现在关键动作段时，不强行修补，回到动画制作重新生成。
