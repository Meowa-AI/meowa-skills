# 组合动作：为实时组装准备动画

组合动作不是一段单独生成的长动画，而是**游戏根据逻辑实时组装**的结果：投掷动作播到出手帧，代码接管投射物；替身跟着主角同时出招；连击一段接一段。后处理的目标，是提前把每一段处理好，让它们在游戏里能被可靠地拼起来。原则见[后处理总览](README.md)。

## 1. 先确定组装方式

动手之前，先说清这个组合在游戏里怎么运行：

- 哪几段动作参与组合，播放顺序是什么；
- 在哪一帧交接：出手帧、命中帧、落地帧，还是收招帧；
- 交接时由谁接管：代码投射物、另一段动画，还是另一个角色。

组装方式决定了每段需要的首尾帧、切点和要记录的元数据。

## 2. 投掷：尾帧交给代码投射物

游戏里飞出去的道具或被扔出的角色，通常由代码控制轨迹与命中。只给首帧让模型自由画飞行物，飞行物容易变糊、被甩出画布截断，也接不上代码投射物。推荐在**生成前**就用首尾帧控制：

1. **首帧：** 投掷者持物（或举起角色）的准备姿势。
2. **尾帧：** 投掷者出手后的姿势，加上用**原素材像素**合成、完整放在画布内半空的飞行物；记录飞行物中心坐标。
3. **提示词：** 只交代“向某方向抛出，飞行物飞到尾帧位置，投掷者全程在画面内”，写明不要大面积特效、不要向后抡。
4. **交接：** 播到交接帧时，代码在记录的坐标生成同一张飞行物图继续飞行；投掷者的收势可拼接已有素材的后续帧。

后处理要点：

- 首尾帧基于同一原素材画布与站位合成。生成结果可能补了几像素边，交接前先用生成段的尾帧和输入尾帧配准求偏移，再平移拼接帧和交接坐标。
- 尾帧约束常让飞行物提前到位、之后原地停着，应截到飞行物**首次到达**交接位置的那一帧再交接，否则会出现明显停顿。
- 被扔出的是**角色本人**时（例如把同伴当武器扔出去），出手前先让场上的这个角色消失，再出现在投掷者手中，保证场上始终只有一个；撞击后由代码让它回到原位。
- 验收时逐帧对比交接前后一帧，飞行物的位置与造型应连续。

## 3. 多角色合击：分别生成，同步播放

两个角色同时出招（替身、合击）时，分别生成各自的动作，在游戏里同步播放，不要把两人放进同一画面生成。

- **记录关键帧：** 每段动作记录起跳、落地、命中等关键帧。
- **同步方式：** 播放时以主角色的进度为准，把从属角色的帧号按关键帧分段对应起来，让双方的关键时刻发生在同一瞬间。两段的总时长不同也可以对齐。
- **站位：** 从属角色贴近主角色，可略有重叠；出招时按各自的出手距离移动到能打中的位置，收招后回到原位。移动用快速冲刺并带残影，不要瞬移，也不要无限前冲。
- **打断：** 主角色被打断时，从属角色也一起回到待机。

## 4. 复杂过程与连段的衔接

- **分段拼接：** 跳起—挥击—落地这类复杂过程按共享关键姿态分段生成后拼接，生成方法见[动画制作](../frame-animation/animation-production.md#复杂过程分段生成再拼接)。拼接后检查接点是否跳位、停顿或速度突变。
- **连段衔接：** 连击的每一段都要有清楚的收势或准备姿势，作为“取消”到下一招的切点；需要更紧凑时，按[加速与裁帧](speed-and-trim.md)裁掉抬手和还原帧。
- 各段按[跨动作锚点验收](../frame-animation/animation-alignment.md)统一锚点，确保切换时不跳位。

## 5. 宣传导出：组合后再导出

游戏里组合动作是实时拼出来的，单独看某一段看不出效果。导出宣传素材时，可以按游戏里的顺序把各段组合成一个动图再导出，例如三连击、传送的消失与出现、倒地与起身。导出方法见[动画导出](../frame-animation/animation-export.md#3-宣传社交媒体资源)。游戏资源仍然交付单段。
