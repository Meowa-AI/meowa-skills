# 端到端：像素风格帧动画

流程：**角色设计 → 高清设计转像素／直接像素生成 → 像素母版验收 → 动画制作 → 像素成品复核**。静态素材任务完成母版验收即可，不自动进入动画阶段。

本篇集中说明像素路线的功能区别、取舍和验收。角色设计读[角色设计](character-design.md)，姿态、画布、首尾帧、生成及整理读[动画制作](animation-production.md)，两者均供高清和像素复用。认证、预算、执行授权、任务恢复与最终产物边界遵循[运行与产物规则](../../references/running-and-outputs.md)。

## 1. 角色设计

按[角色设计教程](character-design.md)确定概念、参考用途、造型、画法和画幅。区分开放探索与严格复刻，先让角色轮廓和核心特征成立，再转换或制作动画。

设计不必先生成高清图：可直接把已确定的概念交给像素生成；也可先探索高清造型，验收后转换。高清先行是可选准备，不保证优于直接像素生成。已有满意设计时不重新发散。

## 2. 高清设计转像素或直接像素生成

### 按风格与尺寸选择路线

四条路线的效果不同，按角色复杂度、尺寸约束和风格选择，不必全部执行。**是否先做高清设计，是可以独立比较的选择**：同一概念和外观提示词可以直接用于像素生成，也可以先探索高清造型再转换，不必把高清设为必经步骤。

在已授权预算内，用户尚未确定这两条路线时，可选一个代表概念，直接像素与高清先行各生成1～2张小样，并排展示造型、像素质感、轮廓辨识度、真实尺寸与细节取舍，交给用户选择。直接像素可能更有复古游戏感，高清先行可用于探索更多样的造型，但实际效果取决于具体设计与生成结果，不预设优劣，也不替用户作审美决定。已有认可的路线就沿用，不必每个角色都重复双路线尝试。

高清母版在转换前也要验收轮廓清楚、关键结构易读、体块与色块简明、全身完整；参考图本身的缺陷会影响转换结果，不能直接归因于像素路线。比较时记录提示词、模型、参考与参数；同时更换多个条件时，不把差异单独归因于其中一个参数。

| 路线 | 做法 | 适合什么目标 | 取舍 |
|---|---|---|---|
| 1. 直接生成像素风格 | 通用生成 Nano Banana 或 Image2.5，提示词明确像素风格 → 完美像素化 | 风格多样、效果优先 | 完美像素化后的实际尺寸事先不确定；偶尔会得到超大像素图 |
| 2. 参考图（可选）＋提示词＋模板 | 可先用通用生成设计高清角色，再接像素生成模板；也可纯提示词驱动 | 稳定性和模板尺寸优先 | 复杂角色选 128px 模板，小角色选 64px 模板；风格受模板约束 |
| 3. 自由分辨率 | 精确像素生成，指定宽高 | 需要指定尺寸，或不希望套用固定模板风格 | 可控制目标宽高；仍需验收实际尺寸、比例和裁切 |
| 4. 超大像素尺寸 | 像素模式的自由画布，选 `xlarge` 和对应比例 | 需要稳定选择超大画布 | 不依赖方案 1 偶然生成大尺寸；仍需检查实际内容和动画输入限制 |

模板不仅提供像素纹理，也可能改变头身比、姿态、造型和色调；精确像素生成允许指定目标宽高，但不是逐像素复制；通用生成＋完美像素化通常更自由，最终像素尺寸却不能预先保证。按实际结果选择，不把一次筛选当作普遍质量排名。定制 workflow 与普通精确生成是不同入口，不能混作同流程的模型对照。

以下示例从 Skill 仓库根执行；安装版替换 runner 路径，`<...>` 为待替换值。下一步输入从任务子目录的 `final_outputs.json` 获取，`--output-dir` 是输出根目录，不是文件名。

### 高清参考如何准备与转换

高清参考先确定外观、姿态、视角和比例。目标是小尺寸像素角色时，可按风格要求轮廓清楚、色块简洁、减少碎纹理；需要清晰外轮廓或黑色描边时明确提出，追求无描边或柔和边缘时不要强加。

纯转换先用短句，例如“将这个角色变为像素化，保持原图外观和动作”，只补必须保持或改变的内容。不必重述整套背景或附带“可用于攻击、防御”，这些可能诱导姿态或装备变化。小幅动作调整可另说；大幅改姿态用[通用姿态准备](animation-production.md#1-准备动作姿态与首尾帧)，不要把它混作纯转换。

同一设计在 96／128px 可读、64px 却反复模糊或碎乱时，可先简化高清母版再试：合并发丝、褶皱、细碎阴影与高光，保留身份、姿态和关键装备，必要时调整比例让关键特征在小尺寸可辨。示例：“保留角色外观、动作和关键装备，为后续64px像素化简化高清设计，减少碎纹理，合并细碎阴影与高光，色块简洁。”简化图先验收，再转换；此补救路线仍需实际验证，不能把约100px的好结果算作64px成功。

### 方案 1：通用生成像素风格 → 完美像素化

先以风格和角色设计为目标，不在提示词里承诺最终精确尺寸：

```bash
python3 skills/game-assets/meowart_api.py general-image-run \
  --generation-model image-2.5 \
  --prompt "像素风格，单个全身银甲骑士，红色披风，侧面持剑，轮廓清晰，纯色背景，无文字" \
  --resolution 1K --aspect-ratio 1:1 \
  --output-dir ./outputs/knight-design
```

可将模型换成 `nano-banana` 比较设计效果；需要保持已有形象时加 `--reference-image <reference.png>`。选出满意的角色图，再做完美像素化：

```bash
python3 skills/game-assets/meowart_api.py pixelate-run \
  --image-file <approved-pixel-style-character.png> \
  --output-dir ./outputs/knight-pixelated
```

逐个角色处理，检查网格、轮廓和真实尺寸。检测可能失败或得到不适合动画的尺寸；此时重新选择角色路线，不把普通缩小当成完美像素化。详见 [像素清理](../../references/pixel-and-hd-assets.md#standalone-pixelation)。

### 方案 2：高清设计（可选）→ 像素模板

想先探索造型时，用通用生成把设计做满意：

```bash
python3 skills/game-assets/meowart_api.py general-image-run \
  --generation-model image-2.5 \
  --prompt "高清游戏角色设计，单个全身银甲骑士，红色披风，侧面持剑，轮廓清楚、色块简洁、减少碎纹理，纯色背景，无文字" \
  --output-dir ./outputs/knight-hd-design

python3 skills/game-assets/meowart_api.py pixel-gen-template-info
```

从当前目录中选择角色模板：复杂造型优先 128px，小角色优先 64px。展示候选的风格、尺寸和预览；用户已指定模板则直接使用，否则遵循 [模板选择规则](../../SKILL.md#choose-general-generation-or-a-template)，不要猜模板名。

```bash
python3 skills/game-assets/meowart_api.py pixel-gen-run \
  --template-name <chosen-character-template> \
  --requirement "单个银甲骑士，红色披风，侧面持剑，保留参考图的盔甲和配色" \
  --reference-file <approved-hd-character.png> \
  --output-dir ./outputs/knight-template
```

已有参考图可以直接传入，不必先生成高清图。没有参考图时，省略 `--reference-file`，并把需求改为独立的角色描述，纯提示词也能驱动模板。模板输出已经像素化，不再串联 `pixelate-run`。

### 方案 3：精确像素生成，自定义宽高

```bash
python3 skills/game-assets/meowart_api.py custom-size-pixel-gen-run \
  --prompt "单个侧面银甲骑士，红色披风，简洁色块，减少盔甲碎纹理" \
  --width 48 --height 80 \
  --output-dir ./outputs/knight-custom-size
```

可加 `--reference-image <character.png>` 保持形象；复杂参考图需检查细节取舍。用于单个对象，不用于资产包。固定模板的风格、尺寸和数量都匹配时可优先方案 2；也可用本方案对照。验收实际尺寸和角色比例，不能仅凭传入宽高就宣布成功。详见 [精确像素生成](../../references/pixel-and-hd-assets.md#custom-size-pixel-generation)。

### 方案 4：自由画布，超大像素尺寸

网页在像素模式选择自由画布、`xlarge` 和所需比例。CLI 的等价入口已经内置 `xlarge`，无需也不支持另传 `--size xlarge`：

```bash
python3 skills/game-assets/meowart_api.py pixel-universal-gen-run \
  --prompt "单个全身重甲骑士，复杂披风和盔甲，像素风格，纯色背景" \
  --view standard --aspect-ratio 3:4 \
  --output-dir ./outputs/knight-xlarge
```

可选比例以当前 `--help` 为准；需要参考图可加 `--reference-image`。`xlarge` 选择的是生成画布，不保证角色占满画面或任意指定像素宽高。

大图能否进入 Pixel 动画，按[像素动画约束](#3-动画制作与像素专属约束)判断，不把 `xlarge` 当作动画兼容保证。

### 像素母版验收与路线固定

- **实际尺寸与主体占比：** 检查文件宽高、内容边界、头身比、留白与完整入框。64、96、128px 按辨识度和用途比较，不按越大越好排序，也不把小角色放在大空画布中冒充目标尺寸。
- **像素表现：** 看网格、色块、轮廓、碎纹理和关键特征在目标尺寸是否可读。预览用最近邻整数倍放大，不平滑或缩小；普通缩小高清图不能代替像素生成。
- **设计还原与透明：** 检查身份、脸、配色、武器／尾巴等必要轮廓、装备位置、动作变化、裁切和实际 alpha。改提示词、模型或输入后重新验收；不凭参数已传入就宣布成功。
- **比较与复用：** 保留编号、原件和参数，说明按同倍数比较真实像素大小，还是用不同整数倍显示成相近大小。选定后记录参考、简化方法、提示词、模型、模板、目标尺寸和后处理，后续复用；只在需求或效果变化时局部重试。排查与设计比较方法见[设计验收](character-design.md#4-验收并固定设计)。

模板、精确像素等像素工作流的输出不再重复完美像素化；通用生成的像素风格图则需检查并完成必要的像素化。母版不合格时回到对应生成路线，不靠动画补救静态缺陷。

## 3. 动画制作与像素专属约束

母版通过后，按[通用动画制作流程](animation-production.md)完成：

1. [姿态与首尾帧](animation-production.md#1-准备动作姿态与首尾帧)：万能编辑使用 `--mode pixel`；先验收动作起始姿势，变身或特效需要限定终点时准备尾帧。
2. [画布与留白](animation-production.md#2-按动作方向选择画布与留白)：按动作轨迹决定比例、四向空间、角色尺度与锚点；同段首尾帧尺寸一致，不同动作无需套同一最大方形画布。
3. [生成小样](animation-production.md#4-生成小样高帧率与分辨率)：使用 `meowa-animation-run --style-mode pixel`，Agent 优先高帧率与合适纯色背景；提高生成分辨率可改善动作清晰度和像素稳定性，不需要先放大角色原始像素。
4. [动作验收](animation-production.md#6-动画校验先整体动作与画布再看细节)：先看整体动作、运动范围和裁切，再看角色稳定与局部像素；代表小样通过后才扩展同类动作。
5. 按用途做[连续动作或分段拼接](animation-production.md#5-连续动作与分段拼接)、[循环整理](animation-production.md#7-循环动作整理)，最后[抠图与交付](animation-production.md#8-抠图复核和交付)。

**Pixel 输入尺寸与留白：** V2 最终输入最长边（含留白）不超过 320px。可动画角色内容尽量在 128×128 内；64px 角色可优先尝试 128×128 以内的动作画布，再按实际动作调整，不作为硬性尺寸。旧入口 Standard／Advanced 的限制不同，见[动画能力参数](../../references/animation-and-video.md#how-to-create-a-high-quality-animation)。超限大图应回到模板或精确像素路线准备适合动画的版本；若要保留超大图，可明确选择 HD 动画并另验收像素边缘，不能静默切换。

**Pixel 处理与最终复核：** 加留白不重采样角色，不通过平滑缩小腾空间。裁帧或裁边时保持原像素、整段一致的画布和锚点，不逐帧紧裁造成抖动。抠图检查硬边、绿色残边及半透明特效，不能把有意义的软 alpha 全部二值化。用最近邻整数倍预览并按实际游戏尺度判断像素抖动、轮廓和细节稳定性；再核对尺寸、帧数、时序、循环和独立音频，登记验收后的最终产物。
